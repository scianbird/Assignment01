General Idea
These are the notes that accompanied my very simple wireframe when I set out to create this website:

Idea - The presentation of the SPACEY site made me think of a travel / tourism board
website. rather than make a website for a real place (in which I could just copy the real tourism website) I instead decided to creatively challenge myself and make a very simple fake website for a fantasy location

places considered: the shire, a pokemon region, Tatooine

Keeping the stretch goals in mind I realised this approach would also be useful, as each location has at least one leitmotif associated - it would then be a very natural choice of which song would play on loading

In the end, I decided to create a sort of tourism/airbnb advertisement for a hobbit house. who wouldn't want to live in one, even it was just for a weekend? (disclaimer a 5ft person wrote that im sure tall people wouldnt like the idea as much)

Reflection
I believe I have achieved all of the requirements, apart from the autoplay function (there are more notes on this in my .js file), however I have suplimented that with giving the user access to the audio controller so that they can choose play/pause, and nesting it within the header so that it is accessible to them no matter where they are on the page.

I'm unsure how much "emotional" reflection is expected in this section, however I believe I have started to lay foundations for a capability of building what I see in my mind. I was able to sit down and build using my own logic, and able to style it somewhat close to what I wanted.
I would like feedback/advice on the styling/design - in particular, I struggled with positioning some elements where I wanted them and I feel like I had to find "a workaround" for those elements. One example of this would be the "back to top" button. I struggled to move it down, and ended up using a minus value for the top margin in order to force it to where I wanted it to be.

The spacing/flex styling in the calendar was also a little troublesome; it existed mainly as a visual aspect for me, as the page felt unbalanced without it. Sort of like a placeholder for an actual useful feature...

A "failure" is the responsiveness of the header - I could not space the nav links out in an accessible space without reducing the space they had access to (setting it to 30%), but this means that when the window is made smaller the nav bar bunches up. I believe theoritically that this could be solved by setting information for min/max screen sizes, but I'm unsure how to do that as of now.

Any feedback you share, or any part of the code you see and think "I personally would never have done THAT", I would love to hear/learn so that my understanding of the theory behind all of this develops
